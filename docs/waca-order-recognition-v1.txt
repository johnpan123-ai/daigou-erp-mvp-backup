Owner 操作
WACA → 來源訂單 → 查看／管理 → 各 SKU 選擇認列 → 填原因 → 預覽 → 確認保存。
認列方式：計入數量／已含原本數量／暫不計入。
這不是匯入更新方式「覆蓋／累加／維持」。選單與預覽本身沒有寫入；無差異不寫入。
多個 SKU 分開選擇，其他訂單相同 SKU 的明細身分不會被更改。
來源訂單不刪除；調整前後、原因、操作者及伺服器時間皆留在不可變更的批次證據。
UI 可展開認列紀錄。回應遺失只做唯讀確認，不自動重送。

數量契約
保留既有 auto = 有效已配對來源數量；管理動作不改來源訂購數量。
本筆差額 = 新 countedQuantity - 原 countedQuantity。
只有相應 SKU 的 manual offset 調整此差額，auto+manual 不得小於零。
計入 → 已含／暫不計入：需要可證明尚未抵銷的 ERP2 額外認列，否則拒絕。
已含／暫不計入 → 計入：有效訂單依當下來源補入；取消、失敗不能補入。
取消、減量與恢復有效沿用來源認列，已回沖不再重複扣除。
INCLUDED／HOLD 持續保存；來源改變時標示需重新核對，不被新 Excel 無條件覆蓋。
匯入 OVERWRITE 若與人工排除決定衝突會拒絕，須先在管理畫面明確處理，不默默覆蓋。

安全與證據
新 RPC：erp_preview_waca_recognition（只讀）、erp_commit_waca_recognition（Owner 原子提交）。
Revision、Restore Epoch、Variant version／數量及預覽計畫均由伺服器重查；Restore maintenance lock 不變。
Restore 後舊人工 COUNT 決定的數量變化，前端及伺服器均拒絕；不能只把匯入計畫改綁新 Epoch 來繞過。
同一 requestId 重複請求只回原 receipt；不同內容重用身分拒絕。
回沖採連續證據鏈：任何中途人工／其他 Variant 變更或 Restore 失配即失去舊回沖資格。
之後的普通匯入不得「洗白」這些已失效的舊數量；只為新額外認列建立新證據。
原 044／074 函式保留為不可供 authenticated/anon 呼叫的 private delegate，外層新增決定／證據保護。
原 073／074 檔案不修改，safeupdate 保持啟用；精確 WHERE 與 row_count 檢查不放寬。
